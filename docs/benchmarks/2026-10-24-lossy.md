# Initial public lossy baseline

Recorded 2026-10-24 after lossy milestone 9, from parent `41f7423`, on an Intel
Core i9-13900KF, x86_64 Ubuntu Linux 7.0.0-38-generic, with
`rustc 1.101.0-nightly (7189d39d9 2026-10-22)` / LLVM 23.1.4 and Cargo's release
profile. The encoder is scalar Rust, synchronous, default preset/method 4.
No CPU-specific compiler options were added. Measurements are observations on
a shared development machine, not timing assertions or a C speed comparison.

[All 28 observations](2026-10-24-lossy.csv) include color qualities 30, 75,
98.5 and 100; nonopaque images also use alpha qualities 0 and 100. Each row
runs in a fresh test process. RGBA generation is outside the timer; import,
cleanup, analysis, alpha trials, VP8 coding and owned RIFF output are inside.
One warm-up precedes five measured encodes; the reported time is their median.
The output is independently decoded after timing.

RGB PSNR uses all three original channels at source pixels whose alpha is
nonzero, without compositing or alpha weighting. Alpha PSNR uses all pixels.
Both use `10*log10(255^2 * sample_count / SSE)`; `inf` means zero SSE. RGB error
against the decoded pinned C reference is zero: every baseline input/quality
combination is also in the exact public C corpus. PSNR measures source color
changes from YUV420 and quantization, not deviation from C.

Image IDs 0/1/2 in the CSV are `support::public_images::image(128,128,pattern)`
patterns 0/2/24, seed `6d2b79f5`. ID 3 is the committed sample; ID 4 uses its RGB
with alpha `(17*x + 13*y) & 255`. File sizes need not be monotonic with quality.

Memory is GNU time's maximum resident set size for the **whole test process**,
including the Rust harness, all five generated fixture images, six sequential
encodes, retained encoded bytes, independent decode and shared libraries. It
is neither an encoder heap-allocation count nor a per-call incremental peak.
Fresh processes measured 4,760–6,672 KiB across these cases; allocator and OS
variation account for some differences. Encoding larger images will use more
memory; these small cases establish an initial reproducible reference.

Run the complete timing/quality measurement with:

```sh
cargo test -p libwebpop --release --test lossy_public public_lossy_baseline -- --ignored --nocapture
```

For a single row and process memory, first obtain the test executable from:

```sh
cargo test -p libwebpop --release --test lossy_public --no-run
```

Then use that executable path (printed by Cargo) in this command. Case 17 is the
opaque real image at quality 75; use cases 0 through 27 to reproduce the CSV.
This excludes Cargo and compilation from the memory measurement:

```sh
WEBPOP_LOSSY_BASELINE_CASE=17 /usr/bin/time -f '%M KiB peak RSS' \
  <test-executable> public_lossy_baseline --ignored --exact --nocapture --test-threads=1
```

The C oracle uses the unchanged `1844042d1ca751e62e61df7617dba19c98588339` pin,
GCC 15.2.0-16ubuntu1 / CMake 4.2.3, Release `-O3 -DNDEBUG`, SIMD/threading off.
The [reference record](../../libwebpop/tests/reference/LOSSY.md) documents the
public corpus and fixture provenance. Existing lossless/near-lossless baselines
remain separate.
